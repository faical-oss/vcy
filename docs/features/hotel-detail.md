# Hotel detail (and the shared detail shell)

Last updated: 2026-11-25

## Purpose
`/hotels/h/<slug>`: one hotel with a gallery, four tabs (Overview, Rooms, Location, Reviews), a sticky booking box with live price and availability, and three similar hotels. The layout is a generic shell (`src/components/sections/detail/`) that package and experience pages will reuse with their own header, tabs and booking box.

## Routes
- `hotelDetail(slug)` in `src/constants/routes.ts` (`/hotels/h/<slug>`, provisional scheme "Option A"); slugs are `detailSlug(name, place)`, e.g. `azure-spa-and-wellness-resort-krabi`. Page: `src/app/(site)/hotels/h/[slug]/page.tsx` (no `loading.tsx`, so an unknown slug is a real 404 on the first request; the lookup and `notFound()` run before anything streams).
- URL parameters of the stay: `checkIn`, `checkOut` (YYYY-MM-DD), `rooms`, `adults`, `children`, `childAges` (one age 0-17 per child, `2,5`), `flex` (`src/helpers/stay-params.ts`), and `room` (the room chosen with SELECT ROOM). All are in `FILTER_PARAMS`, so a dated or room URL is noindex,follow (header) with the clean canonical. The booking form writes the stay to the URL by itself once the dates are valid (250 ms after the last change); the URL is not written while a child has no age. The outlined "Check availability" button shows only while the stay is not valid.
- "Back to search results" goes back in the browser history when the visitor came from another page on this site, otherwise it follows `ROUTES.hotels` (`/hotels`, which is not a page yet and returns 404; decided, to be replaced when a search or hotels page exists).
- `/checkout` (`src/app/(site)/checkout/page.tsx`): a noindex STUB, only with `FEATURE_CHECKOUT_STUB=true` (mocks, not production); otherwise a 404. It shows the chosen hotel and dates and prices nothing.

## Availability
See [availability-flow.md](availability-flow.md): the live price streamed per request described below is replaced by a client-side flow (no `searchParams` on the page, same HTML for every search).

## Data
- `ICatalogService.getHotel(slug)`, `getSimilarHotels(slug, limit)`, `listHotelSlugs(limit)` and `HotelDetail` (`src/interfaces/catalog.ts`, `src/interfaces/detail.ts`): static content only (name, photos with alt text, description, amenities, good to know, rooms with indicative "from" prices, transport facts, attractions, reviews, location). Prices are `Money`.
- Live price: `IAvailabilityService.getHotelAvailability(query)` (`AvailabilityQuery`, `AvailabilityResult`); `getAvailabilityService()` in `src/services/index.ts`. Reviews: `IReviewService.submitReview`. Mock only: `src/mocks/services/availability.mock.ts`, `review.mock.ts`; per-hotel mock content in `src/mocks/fixtures/catalog/hotel-details.ts` (one seed per catalog hotel, built by `hotel-detail-builder.ts`).
- The mock rooms' entry price equals the card price; rooms above it are tiered. Mock availability is deterministic: about one stay in seven is "sold out".

## Caching
- Static shell: `getHotel`, `getSimilarHotels` are `"use cache"`, `cacheLife("hours")`, tags `catalog`, `hotel:<slug>`, `category:<type>` and one `hotel:<slug>` per similar card (`src/features/catalog/get-catalog.ts`). `generateStaticParams`: `getHotelSlugs()` (best `STATIC_PARAMS_LIMIT`, seed list fallback).
- Live price: `getHotelAvailability` (`src/features/availability/get-availability.ts`) is cached for `AVAILABILITY_TTL_SECONDS` = 60 (`cacheLife({ revalidate: 60, expire: 61 })`, no tags). The key is the arguments: hotel, check-in, check-out, rooms, adults, children, flexibility and currency (finer than hotel + dates + travellers + currency, because the price depends on the room count and the adult/child split). It is fetched only for a valid stay.
- `liveRecheck()` (same file): uncached price check, the placeholder the real checkout will call. It exists and is NOT called anywhere yet.
- RESERVE NOW (`ReserveButton`, a server component in `<Suspense>`): enabled only with the checkout stub flag on, valid dates and a live price; it links to `/checkout`. It prices nothing itself.
- `searchParams` are never awaited in the page: they are read only inside `<Suspense>` (`AvailabilityPanel`, `RoomLivePrice`, `BookingForm`), so the shell stays prerendered and the live price streams in. Verified on the built server: the clean URL has no live total in its HTML.

## SEO
- `urlPolicy` type `detail` (not a separate "hotel" type, so packages and experiences reuse it); `pageSeo()`; title `<name>: <badge> in <city>`, description from the first sentence of the description.
- JSON-LD: `BreadcrumbList` (`PageBreadcrumb`, Home > Hotels > type > name, same crumbs as the visible breadcrumb) and `Hotel` (`lodgingJsonLd`: name, URL, image, description, address). No `aggregateRating`, Review or price while `USE_MOCKS=true` (`ratingAllowed()`, `priceAllowed()`).
- Exactly one `h1`; the first gallery image is `loading="eager"` with `fetchPriority="high"` (`priority` is deprecated in Next 16), the others lazy; every photo has alt text. In the sitemap via `getCatalogSitemapPaths()`.

## Header order
`DetailShell` has no CSS reordering: the page reads header, gallery, tabs in DOM, visual and focus order at every width (from `lg` the gallery and tabs are the left column beside the sticky box). In the header (shared by hotels, experiences and packages, `DetailHeader`) the DOM is: the actions (Back, then Favorite and Share side by side), the breadcrumb, the title, the subtitle, the meta (the rating line and review count, the location, the key facts), then the badges; the meta row is `display: contents` below `md`. From `md` the actions are placed on the right by grid placement, the badges move above the title and the rating to the end of the meta row with `order` (non-interactive text; the desktop design is unchanged). The title wraps over as many lines as it needs. `RatingLine` keeps the stars and the score together and wraps the review count below them when the line is full (320px); the card `Rating` and the review form's stars follow the same rule (text on one baseline, centred on the stars). Tested in `detail-header.spec.ts`.

## Photo gallery modal (Airbnb style, shared by hotels and experiences)
- **Open:** a click on any photo of the page gallery, the "+N more" tile, or the two links below `md` opens the full-screen modal (`PhotoGalleryModal`, `src/components/sections/detail/photo-gallery-modal.tsx`, opened by `DetailGallery`). A click on a specific photo scrolls the modal to that photo's section (the first group is already at the top, under the strip). The page's visible photos stay in the server HTML; the modal's content mounts on open.
- **Layout:** a strip at the top, fixed (sticky) while the sections scroll, with one thumbnail and label per group (one click scrolls smoothly to the section, which stops just under the strip; the current group is highlighted as you scroll; keyboard-focusable buttons); then one section per group: the title on the left (sticky from `md`), the grid on the right (one full-width photo, then two side by side, repeating, all with fixed aspect ratios and lazy loading). Below `md` it is one column with the title above the grid and no sticky title.
- **Dialog behaviour:** role dialog and aria-modal, label "Photos of <name>", Radix focus trap, scroll lock and focus return (to the photo or tile that opened it), Escape and the close button close it. It lives in the `#photos` hash (`useHashDialog`): opening adds a history entry, so the browser back button closes it and returns to the page's tab hash (`#rooms`) without scrolling; closing goes back exactly once. A link that already ends in `#photos` opens it.
- **Lightbox:** a photo in the modal opens the existing `PhotoLightbox` (arrows, keyboard, counter over all photos); closing it keeps the modal and its scroll position and returns focus to that photo.
- **Data:** `GalleryGroup { id, title, thumbnail, images[] }` (`src/interfaces/detail.ts`), optional `galleryGroups` on `HotelDetail` and `ExperienceDetail`. Hotels: Overview, one group per room type, then Pool, Restaurant, Lobby. Experiences: Overview, Accommodation, Activities, Food, Facilities. Mock (`mocks/fixtures/catalog/gallery-groups.ts`); `TODO(api)`: images grouped by category. Without groups the modal is one "All photos" section and no strip (`resolveGroups`).
- **Videos in a group:** `GalleryGroup.videos` (`GalleryVideo { url, title, poster }`) show a poster tile with a play button first in their section (the Overview group has one in the mock, hotels and experiences). It opens the same player as "Watch video" in its own dialog; closing it keeps the gallery and returns focus to the tile. `TODO(api)`: the real videos and posters. The page's "Watch video" tile (experiences, from `videoUrl`) is unchanged.

## Rooms and guests rules (2026-11-18)
- rooms >= 1, adults >= 1, rooms <= adults, rooms <= 8. More rooms raise the adults to match; fewer adults lower the rooms; fewer rooms leave the adults alone (`src/helpers/guest-rules.ts`, tested).
- Room selection: quantities per room type (`src/helpers/room-selection.ts`) add up to the rooms searched; "+" and "Select room" are disabled everywhere once reached (with one room searched, choosing another room swaps). Selection lives in the store only (lost on reload); the first chosen room is mirrored in `?room=` for the booking box price.
- Continue needs N = M, valid dates and a capacity pass (adults fit the rooms' adult places; adults + children fit the occupancy). It links to the checkout stub only with `FEATURE_CHECKOUT_STUB`; otherwise it stays disabled.
- Open (mocks, `TODO(api)`): the summary total uses live one-room prices when there is a valid stay and an estimate (indicative nightly price x nights) otherwise; the availability request carries only the room count, not per-room occupancy or child ages, so live per-room prices for a mixed selection are not available; the room types are the same ten for every hotel.
